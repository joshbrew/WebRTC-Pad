Linux desktop setup

Controllers and browser video work independently of the options below. Audio, mouse access and desktop cursors all start off.

1 · Prepare native tools

Run sh linux/shortcuts/07-Host-Native.sh. Install Python 3, FFmpeg, libpulse, libX11, libXext and libXtst through your distribution. On Ubuntu/Debian: sudo apt install python3 ffmpeg libpulse0 libx11-6 libxext6 libxtst6 x11-xserver-utils. Use your desktop’s existing PulseAudio or pipewire-pulse service; do not replace a working audio stack. Keep the app and browser running as your normal user.

2 · Choose sound and video

In an X11 session, choose Native sharing, select the game window or desktop and check the preview. Enable Include native audio to include that app’s playback, or system playback for the desktop.

With browser video, enable Use native audio instead of browser audio, then choose the sound app or explicitly choose system audio. On Wayland, use browser video; native system audio can accompany it. The app cannot enumerate native Wayland windows for the sound-app list.

Application sound includes the selected process and its active child processes. A refused app monitor reports an error; system audio and microphones are never substituted. Stopping audio releases capture without moving playback or changing volumes.

3 · Approve controls separately

For X11 window-only mouse control, select that exact game window, start a session, and enable mouse access under Guest cursors & desktop access. Covered or minimized windows cannot be clicked. Resizing updates input coordinates; changing or closing the source revokes access. Entire-desktop control requires its own confirmation. Guests must also turn on their mouse/typing options.

Enable Show guest cursors over desktop apps for colored, click-through markers. Labels are optional. These markers do not take keyboard focus; Linux markers can appear in captured video, and some fullscreen games may cover them.

Wayland restricts global input and overlays. Those controls are disabled in the app; an X11 login session is required for this backend. Desktop permissions never silently expand from one window to the whole screen.

More detail and acceptance-test limits: system/docs/linux-desktop.md.

Receiving controllers and local app input

The Linux virtual-gamepad endpoint needs Python 3 and access to /dev/uinput or /dev/input/uinput. It works on X11 and Wayland independently of desktop control. Native receiving pauses outgoing controller sharing to prevent feedback loops. Use App-only if uinput access is unavailable; separate keyboard/mouse/MIDI streams and the local API do not need uinput. Start-Linux.sh prepares both roles. Device permissions remain under your control; do not run the app as root.
