Block local controller input

This toggle is on by default in the local Join app. Ready connected controllers are reserved automatically, even before you connect to a friend. They keep working in the background. Turn the toggle off to use controllers in local apps too. Video is optional.

1 · Prepare your computer

Windows

Close the app console and run windows/shortcuts/09-Guest-Exclusive-Setup.cmd. It prepares the reader and installs/checks HidHide automatically. To also block local keyboard/mouse input, run npm run setup:guest -- --all-devices. Reconnect controllers that were already connected during driver installation, or restart Windows if requested. The app checks whether the driver is attached before offering local input blocking. Keep Windows security features enabled if a driver cannot load. Close and reopen local controller apps, including Steam, after enabling isolation to discard older device handles.

Linux

Install 64-bit Python 3.9 or newer through your distribution, then close the app and run sh linux/shortcuts/09-Guest-Exclusive-Setup.sh. No input driver is installed. The device list shows the selected device’s /dev/input/eventN path and any missing read permission.

For temporary access, grant only your user read permission on the event node you identified, for example sudo setfacl -m u:YOUR_LOGIN:r /dev/input/eventN. Replace both placeholders with your login and the correct device path. Revoke with sudo setfacl -x u:YOUR_LOGIN /dev/input/eventN. Unplugging can recreate the node; refresh and select it again. The acl package provides setfacl. Do not grant access to every input device or run Node/the browser as root.

Exclusive evdev grabs work on X11 and Wayland. This is guest device reading; native screen capture and host desktop input have separate compositor requirements.

macOS

Install 64-bit Python 3.9 or newer from python.org or your existing package manager. Close the app and run mac/shortcuts/09-Guest-Exclusive-Setup.command. In System Settings → Privacy & Security → Input Monitoring, allow the terminal/Python launcher if needed, then reopen the app.

No driver is installed. macOS may refuse exclusive access to built-in, composite or protected HID devices. A refused device is released and not shared. Raw HID controllers use Controller & keyboard mapping after joining.

2 · Connect and play

Run 02-Join or choose Join in the app. The Controllers list shows connected devices and assigned players. Open Advanced only for setup or input options; connected controllers are reserved automatically with Block local controller input on. Open your friend’s invite and send the reply back. Once connected, press a button on each controller you want to use. Idle controllers do not take a player spot.

For a keyboard or mouse, open Advanced: block a keyboard or mouse. Choose the devices and whether keyboards control a gamepad or type on the host. The host must allow the requested input. Click Use selected devices on host and confirm. Release held keys/buttons before starting and keep another keyboard or mouse available for release. Advanced keyboard/mouse blocking requires a live call.

3 · Release or reconnect

Turn off Block local controller input, switch to Host, or close the Join page to release controllers. Ending a call keeps controller blocking active while the Join page stays open. Refresh after connecting or reconnecting a controller.

For a keyboard/mouse group, Release devices, pause, disconnect or Ctrl + Alt + Esc releases the selected group. Losing the host connection or its required permissions releases keyboard/mouse capture too. Select keyboard/mouse devices again to resume; controller-only blocking can resume automatically.

Linux/macOS release exclusive OS handles when the reader exits; a separate guardian stops a stalled reader. Windows HidHide rules use a recovery journal: after an interrupted shutdown, reopen the app to recover or run .local/tools/guest-input/webrtc-pad-guest.exe --recover. Preserve the journal until recovery finishes.

HID gamepads use their controller collection; XInput also needs its associated XUSB access path. Unsupported device identities stay unavailable. Physical PS4 blocking has been checked; other models and Xbox/XInput still need equivalent hardware checks. HidHide may not stop every Raw Input reader or an app with an older open handle. Close and reopen local controller apps after blocking begins.

Native Linux/macOS paths are implemented with automated adapter tests. Real hardware isolation, OS permissions and reconnect behavior still require validation on those systems. See system/docs/guest-device-isolation.md for full limits.
