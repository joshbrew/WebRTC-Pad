# Mac native hosting (experimental)

Run `mac/shortcuts/07-Host-Native.command` on macOS 13+. Apple Command Line Tools are required (`xcode-select --install`). FFmpeg is needed for playback-audio Opus encoding; `brew install ffmpeg` works with an existing Homebrew installation. The setup builds the Swift helper for this Mac and the existing Pion WebRTC helper. No kernel extension or virtual audio driver is installed. Open **Settings & troubleshooting → Mac audio & desktop setup** for permission buttons.

The helper uses ScreenCaptureKit for selected-window/main-display capture, GPU scaling and app/system playback audio. VideoToolbox encodes H.264 directly from native pixel buffers. RTP packets travel over loopback to Pion; raw video does not pass through Node or a browser canvas. Hardware acceleration is requested and the actual hardware/software result is reported. Audio is converted to 48 kHz stereo PCM, then encoded with the existing FFmpeg Opus path. The microphone is never captured. App audio includes that app's other windows, but not unrelated apps. Selecting app audio never falls back to system audio.

Screen Recording and Accessibility are separate macOS permissions. The setup script does not request either. Permission requests happen only through the explicit buttons in the Mac guide. macOS may attribute a command-line helper's permission to the launching terminal. Restart as directed by macOS. Locally built helpers are ad-hoc signed with a stable identifier; a rebuild can require renewing permission. Protected content, secure input and exclusive fullscreen are subject to OS restrictions.

Window input pins the CGWindowID, PID and process launch time. Public Accessibility APIs must uniquely match that window's current bounds/title. Every pointer event requires a hit on that AX window; keys require it to be the focused window. Window-scoped events are posted to the selected process, never globally. Unidentifiable, ambiguous, covered, closed or minimized windows are denied. Scope changes release held input, and a 500 ms watchdog releases stale keys/buttons. Whole-screen input uses a separate explicit host grant and stays within the main display. This supports cooperating desktop apps, not security isolation from a malicious app running as the same OS user.

Cursor markers are borderless, nonactivating AppKit panels with `ignoresMouseEvents`, clipped to the selected source, colored per guest and hidden after inactivity. They may be included by screen capture. Fullscreen Spaces and games may cover them. The helper uses no private AX window-ID functions and does not bypass permissions or protected dialogs.

Validation: portable Node/server and browser fixtures cover capability gates, source/process identity, permission route authorization and audio/video independence. `node system/scripts/build-macos.mjs` compiles and runs an RTP fragmentation/geometry self-test without capture/input permissions; macOS CI runs it too. **Actual Mac audio, capture, overlay and input behavior has not been verified on Mac hardware in the Windows development environment.** Before release, test selected-window and main-screen video/audio, Retina scaling, two overlapping windows, permission denial/revocation, moving/resizing/closing windows, fullscreen Spaces and releasing held input on disconnect. Mac virtual controllers remain separately experimental; these desktop APIs do not remove that limitation.
